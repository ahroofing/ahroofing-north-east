## Executive SEO Summary

The current site is a strong conversion-first one-page brochure, but it is structurally too narrow to rank well for the full range of commercial searches the business wants to win. Right now one URL is trying to rank for broad flat roofing, repairs, replacement, commercial roofing, storm damage, systems, and service-area intent at the same time.

The highest-value SEO change is not a meta-tag tweak. It is a shift from a single-page structure to a focused multi-page structure built around real search intent:

- one strong homepage
- a small set of service pages
- a few genuine area pages
- a project/case-study section
- a small resource section answering pre-conversion questions

The current homepage should remain the brand and broad-value landing page, but dedicated URLs should carry the ranking load for the most commercially valuable searches.

## 5. Technical SEO Audit

## Genuine SEO problems

### One-page architecture

This is the main SEO limitation. It restricts topical depth, internal linking, title targeting, and crawlable relevance for distinct commercial intents.

### Sitemap too thin

Current sitemap has only one URL. Once service, area, guide, and project pages exist, every indexable canonical URL should be added.

### Missing `WebSite` structured data

The homepage currently has `RoofingContractor` markup but not `WebSite` markup for site name preference.

### No breadcrumb system

Once the site becomes multi-page, breadcrumb navigation and `BreadcrumbList` schema should be added for service, guide, area, and project pages.

### Current site has no crawlable service URLs

Anchor links are fine for users but weak for SEO compared with dedicated URLs.

## What looks good already

- `robots.txt` is permissive
- homepage canonical exists
- social metadata exists
- JSON-LD exists
- JS rendering risk is low because the content is present in HTML
- image markup is mostly good
- mobile and accessibility fundamentals are sound

## Optional improvements

- Add `lastmod` values to sitemap entries once the site expands
- Ensure a custom 404 page exists on the live host
- Add compression and long-cache headers on static assets if the host does not already do this
- Convert the best remaining source images to smaller optimized versions if any originals are still served

## Technical checklist

- Crawlability: confirm with live crawl after deployment
- Indexability: verify in Search Console
- robots.txt: keep live and simple
- XML sitemap: expand to all canonical pages
- Canonicals: self-referencing canonicals on all indexable pages
- HTTP status codes: confirm 200 / 301 / 404 behavior live
- Redirects: standardize trailing slash behavior
- Duplicate pages: avoid service/area clones
- URL structure: short, readable, lowercase slugs
- HTTPS: confirm enforced on live host
- Mobile usability: re-check after multi-page expansion
- Core Web Vitals: test live URLs
- JavaScript rendering: low risk, still verify live
- Heading hierarchy: maintain one H1 per page
- Image optimization: continue using AVIF/WebP, dimensions, lazy loading
- Broken links: crawl after launch
- Orphan pages: avoid by linking every new page from at least one hub
- Pagination: not needed yet
- hreflang: not needed unless multi-language
- Open Graph: keep page-specific
- Structured data: expand carefully with visible support
- Breadcrumbs: add once multi-page
- 404 handling: custom useful 404 page

## 7. Structured Data Recommendations

Use only markup that the visible content genuinely supports.

### Homepage

- `WebSite`
  - helps Google understand preferred site name
- `Organization`
  - helps Google understand brand details
- `RoofingContractor` or `LocalBusiness`
  - helps Google understand the business type, contact details, and service area

Recommended additions if true and visible:

- `logo`
- `telephone`
- `email`
- `areaServed`
- `sameAs` links
- `address` only if you want a public address shown

### Service pages

- `Service`
  - helps search engines connect the page to the specific offering

### Project / guide pages

- `Article`
  - useful for case studies and guides with publish/update info

### Breadcrumbs

- `BreadcrumbList`
  - add once there are multi-page navigation paths

### FAQ markup

- Only use `FAQPage` if the FAQs are visible and accurate.
- Do not expect FAQ rich results for this business site. Google said FAQ rich results are now shown regularly only for well-known government and health sites.

### What not to add right now

- Review snippet schema for placeholder / unverified testimonials
- Product schema
- Event schema
- Multiple fake LocalBusiness entities for every town page
