# Design System: AHRoofing North East

## Overview

**Creative North Star: "Night Shift, Day Proof"**

The site now runs on two registers instead of one continuous navy field: white/cream daylight sections carry the actual proof (services, credentials, testimonials, FAQ), while a small number of deliberate near-black navy bands — the hero, the portfolio strip, the emergency band, the contact card, the footer — punctuate the scroll like dusk falling. Every dark band still closes on the same three-way action (call, text, email); the light bands are where the visitor reads and decides. Amber is the only committed accent color: every action uses it, and the one "most-recommended" card in the Why Choose Us grid is marked with an amber-tinted background and inset amber border rather than a second hue. A lime accent was tried for that single highlight in an earlier pass and removed 2026-08-15 — see Colors below.

The site grew from one page to several during the 2026-08-15 technical-improvement pass. Four flat-roofing service pages were added and then removed again 2026-08-16 at the client's request. **Correction, verified 2026-08-22: no `projects/` directory exists on disk.** The three project case-study pages this section previously described as "remaining" are not present — either they were removed in an unrecorded pass or this paragraph was never accurate. `index.html` is currently the only page. Treat any reference elsewhere in this file to `projects/*.html` pages as stale until a real audit confirms otherwise; this correction only fixes this paragraph, not every downstream mention (see Portfolio Card and Multi-Page Structure, which still need a full pass).

This redesign replaced the prior all-navy visual world at the user's request, using a competitor template screenshot as a pinned layout reference. The reference's structural ideas were adopted — an asymmetric hero with a floating stat card, an offset photo collage, a static numbered service list (all descriptions always visible, not an accordion) beside a lead photo, a dark portfolio band, a 4-up feature grid with one highlighted card, image-led CTA and contact sections — but its eyebrow labels ("About Us", "Our Services" in small caps above headings) and decorative 01/02/03 section numbering were deliberately dropped; both are refused by this project's craft floor regardless of brief, since neither carries information the reader needs here.

**2026-08-22 structural pass:** a second reference ("Apex Arc," an architecture-firm template) was pinned for a targeted redesign of four sections — colors, tokens, and every other section left untouched. Hero flipped from bottom-anchored to top-anchored content with a new signature move borrowed from the reference: a primary CTA that straddles the photo's bottom edge (`.hero-float-cta`), in this project's own button radius, not the reference's pill. About's photo collage was replaced with a real-facts-only stat grid (no fabricated project counts, no client logos — this business has neither). Flat Roofing Services became a horizontal scroll-snap carousel with functional prev/next arrows. Recent Work became an asymmetric bento grid tagging stages of the one real documented job, rather than borrowing the reference's multi-project layout for content that doesn't exist. Full detail under each section's own entry below (Hero, About Stats, Service Group Cards, Portfolio Card).

**Key Characteristics:**
- White/cream ground for reading sections; near-black navy reserved for a handful of deliberate dark bands, never the default
- A single amber accent for every action, including the one scoped "most-recommended" feature-card highlight — no second hue
- Large-radius, softly-shadowed surfaces throughout; offset photo collages replace single static portraits
- Poppins (rounded geometric sans) throughout, for both display and body — matches the pinned reference's actual typeface; a second-pass correction after the first redesign kept the original Archivo/Public Sans pairing and the user asked for closer fidelity
- A compact, rounded-corner hero banner sitting inside page margin, not an edge-to-edge full-viewport-height section — the previous 92vh bleed hero was the main source of the "stretched out" feeling this revision fixed

## Colors

Two-register strategy: white/cream carries reading sections, near-black navy owns a fixed set of dark bands, amber is the one committed action color and the one highlight color.

### Primary
- **Navy 950/900/800** (`#0b1220` / `#121b2e` / `#1a2740`): the hero, the portfolio band, the emergency band, the contact card, the mobile nav panel, and the footer — nowhere else. `--ink` (`#16233d`) is the separate, lighter navy used for heading text on light backgrounds; it is not interchangeable with the dark-band tokens.

### Secondary
- **Amber 500** (`#f28c28`): every call-to-action, badge icon chip, and the hero's "Trust" emphasis word. Never used as a large background field with light text on top — the Navy-on-Amber Rule below still governs.
- **Amber 50/100** (`#fef6ec` / `#fdecd8`): the tint used for the one "most-recommended" feature card (`.feature-card.is-highlight` — `amber-50` fill, inset `amber-500` border) and for icon chips throughout. A lime accent (`#d7e94c`/`#bdd022`) filled this same highlight role in an earlier pass; it was removed 2026-08-15 to keep the palette to navy/white-cream/amber/grey — one fewer color to keep in sync, and one less thing for a "most-recommended" signal to compete with.

### Neutral
- **White** (`#ffffff`): default section background.
- **Cream** (`#faf8f3`): alternating section background — a warm off-white, not pure grey, distinguishing "reading" sections from each other without needing a hard border.
- **Grey 150/100** (`#e6e9ee` / `#f1f2f5`): card borders, chip fills, tag pills.
- **Ink-soft** (`#57616f`): secondary/body text on light backgrounds — tuned to clear 4.5:1 on both white and cream.

### Named Rules
**The Navy-on-Amber Rule.** Any text sitting directly on the amber field (buttons) is set in navy-950, never white — carried over unchanged from the prior system since it's a genuine accessibility constraint, not a style preference.

**The One Highlight Rule.** Exactly one card, once, in one section, gets the amber-tinted "most-recommended" treatment (`.is-highlight`). The moment a second element reaches for it, the signal stops meaning anything — this replaced an equivalent lime-based rule that governed the same constraint before lime was removed.

**The Two-Register Rule.** A page section is either a light reading section (white or cream) or a dark proof/action band (navy-950 gradient) — never a mid-tone. No section uses a grey or muted-navy field as its own background; the contrast between registers is the point.

## Typography

**Poppins** (self-hosted static weights 400/500/600/700/800), used for both display and body — matching the pinned reference's actual typeface exactly rather than approximating its character with a different family. This replaces the first redesign pass's Archivo/Public Sans pairing, which the user asked to change for closer fidelity to the reference. Heading weight dropped from 800 (ExtraBold) to 600–700 (Semibold/Bold) to match the reference's more moderate weight, and the type scale was reduced roughly 20–25% across the board — the reference's headlines are noticeably more restrained than the first pass shipped.

### Named Rules
**No eyebrow labels.** The reference this redesign is pinned to uses small tracked labels ("About Us", "Our Services") above every heading. This system refuses that pattern: every heading carries its own weight without a kicker, per the project's craft floor, which bans eyebrows outright rather than treating them as a default.

**No decorative section numbering.** The reference marks its service list 01/02/03/04. This system uses icons instead — the sequence itself doesn't carry information the reader needs, so numbering it would be decoration wearing the reference's clothes rather than a real structural device.

## Layout

Single-column content in a `max-width: 1240px` container with fluid inline padding. Section rhythm is unchanged (`clamp(4rem, 9vw, 7.5rem)` standard, `clamp(3rem, 6vw, 5rem)` tight).

**Current homepage section order** (reordered 2026-08-17 to put Additional Services right after the main Flat Roofing Services instead of near the bottom — this supersedes every earlier sequence documented in prior revisions of this file): Hero (dark, its own exception) → **cream** Flat Roofing Services (`#services`) → **white** Additional Services (`#additional-services`) → **cream** Flat Roofing Systems (`#roofing-systems`) → **navy** Recent Work (`#projects`) → **white** Testimonials (`#testimonials`) → **cream** 10-Year Guarantee (`#guarantee`) → **white** Why Choose Us (`#why-choose-us`) → **cream** About (`#about`) → **white** Emergency (`#emergency`) → **cream** FAQ (`#faq`) → **white** Contact (`#contact`) → **navy** footer. Moving Additional Services required re-flipping `roofing-systems`/`emergency`/`faq`/`contact` to keep the alternation valid (each one swapped white↔cream to stay unlike its new neighbours) — `additional-services` itself didn't need to change since it was already white. No two adjacent sections share a register — verify this with `getComputedStyle().backgroundColor` on both sides of a seam whenever a section is inserted, removed, or reordered; it has broken silently before (the 2026-08-14 audit) and would again.

New structural patterns introduced this revision:
- **Offset photo collage** (About section): two images at different sizes, overlapping, with a floating amber stat badge anchored at the intersection — replaces the prior single monogram portrait.
- **Floating stat card on the hero photo**: a white card with a dark icon tile, positioned absolute over the hero image at desktop widths only (≥700px) — echoes the reference's hero motif without inventing a fake customer count.
- **Dark portfolio band** (Recent Projects): three image cards with a bottom-gradient caption overlay and two tag chips each, on a navy-950→900 gradient section — each card is now a full `<a>` wrapper linking to its own project case-study page (see Multi-Page Structure), with a "View project" text affordance; needed `position: relative; z-index: 1` on the link once the pre-existing `::after` gradient overlay started intercepting its clicks.
- **Flat Roofing Systems, Guarantee, and Additional Services** are new sections added in the 2026-08-15 pass — see their own component entries below.

Mobile carries a fixed bottom contact bar (`--mobile-contact-h: 64px`, safe-area-aware via `env(safe-area-inset-bottom)` — applied once, on `.mobile-bar` itself, not duplicated on its child links). It's visible below the `.nav-links`/`.nav-toggle`/`.mobile-nav` breakpoint, which moved from 900px to **1100px** in the 2026-08-15 pass (the header was crowding `.nav-links`, `.nav-call`, and the toggle together below that width) — the mobile bar now covers a correspondingly wider range of viewport widths. The hero's original horizontally-scrollable badge row was later replaced with a single compact trust line and no longer needs the "keep clear of the fixed bar" scroll-strip treatment the Do's/Don'ts below used to describe.

## Elevation & Depth

Unchanged two-layer soft-shadow system (`--shadow-sm` / `--shadow-md` / `--shadow-lg`), retuned to a navy-950-based rgba rather than the prior navy-deep, so shadows read slightly cooler/darker to match the new near-black dark bands. `--shadow-amber` is used by the About section's floating stat badge; primary CTA buttons moved to a flat, minimal shadow as part of the Apple-style button treatment (see Buttons below).

## Shapes

Radius scale corrected this pass by directly cropping and zooming into the reference screenshot at native resolution (not eyeballing a scaled-down view) — the earlier two attempts at "rounded rectangle" buttons and cards were both still too rounded. The reference is a near-sharp design: `0px` for cards, portfolio tiles, FAQ rows, and photos; full pill for tags, chips, and the service-list number badges. If a future change makes something look "too rounded" again, measure it — don't estimate from a thumbnail-scale view of the reference.

Buttons briefly departed from the near-sharp reference for an Apple-style pill treatment (see Buttons below), then were reverted 2026-08-15 — `--radius-btn`/`--radius-ghost` now alias `--radius-sm`/`--radius-md` again, so the whole button system matches the rest of the shape scale.

## Components

### Header / Nav Toggle
`.nav-toggle` (the hamburger button, <1100px) had zero interactive feedback until fixed 2026-08-16 — background and border never changed on hover, active, or open. Now: `grey-100` on hover, `grey-150` on `:active`, and when the panel is open the button itself fills navy-950 with a white icon (`darker on hover: navy-900`) so it visually reads as "activated," matching the dark panel it controls, instead of the icon-swap being the only sign anything happened.

### Footer
`.site-footer` and `.mobile-bar` both carry `on-dark` as of 2026-08-16 (previously neither did). Without it, `:focus-visible` on every link inside them fell back to the base rule's `navy-900` outline against a `navy-950` background — 1.09:1 contrast, functionally invisible. `on-dark` routes them to the same `amber-400` outline (9.06:1) the mobile-nav panel already used; same bug, same fix, two more places it existed.

`.footer-list` (10 Quick Links) splits into 2 columns of 5 at ≥760px via CSS Grid (`grid-auto-flow: column; grid-template-rows: repeat(5, auto)`) — fixed 2026-08-16. In one column it stood 447px tall next to the ~150-180px brand and contact columns beside it, visibly lopsided; splitting brings it to ~247px, closer to balanced. Uses explicit `grid-template-columns`/`grid-auto-flow`, not `column-count` — `.footer-list` is `display: grid`, and CSS multicol properties are silently no-ops on a grid container (tried `column-count` first, verified via element positions that it did nothing, then switched to grid's own column-flow). If the Quick Links item count ever changes from 10, update `grid-template-rows: repeat(5, auto)` to match the new per-column count.

### Buttons
Near-sharp (`4px`/`6px` — `--radius-btn`/`--radius-ghost`, aliasing `--radius-sm`/`--radius-md`) on both solid primary and outline secondary/ghost buttons, matching the reference's own button treatment. Amber-filled primary with navy text, transparent secondary with navy or white border depending on background. Label weight is semibold (600), matching the reference's button-label weight.

Buttons briefly went full pill (`999px`) for one revision — an explicit "make the buttons more Apple-like" request — then were reverted to this near-sharp treatment 2026-08-15 as part of reconciling the site against an external technical-improvement plan that called for restoring the reference's actual radius scale. If pill buttons are ever wanted again, `--radius-btn`/`--radius-ghost` are the only two variables to change; nothing else in the shape scale depends on them.

### Mobile Nav
Fully redesigned in a 2026-08-15 pass — the previous version (a 100vw full-bleed navy takeover with giant `1.9rem` headline-weight links) was explicitly rejected by the client ("I hate it") for feeling heavy and overwhelming with no visual interest beyond text size. Replaced with a compact slide-in panel: `width: min(85vw, 360px)`, sliding from the right with `border-radius: 20px 0 0 20px` on the leading edge, `box-shadow` for depth, over a `.mobile-nav-scrim` backdrop (`rgba(11,18,32,0.55)`, fades in/out, click-to-close) that dims but keeps a visible sliver of the page behind it rather than hiding it entirely.

Internals: a brand header row (logo + wordmark) at the top for context now that the page isn't fully hidden; each nav link drops from `1.9rem` to `1.05rem` and gains a small `1.15rem` leading icon (amber-400, one per section — house/wrench/shield-check/user/star/help-circle/mail) with a hairline divider between rows, replacing undifferentiated stacked headlines with a scannable icon list. Items stagger in (`opacity`/`translateX`, ~35ms cadence per row) on open rather than all appearing at once; respects `prefers-reduced-motion`. CTA buttons unchanged in content (Call + Text), still pinned to the bottom via `margin-top: auto`.

The `inert` treatment on `#main`/footer/mobile-bar while open (see main.js) still applies unchanged — the scrim blocks pointer access to the dimmed sliver, but keyboard Tab order still needs `inert` to skip it, so both mechanisms stay in place together. The header's brand link and `.nav-links`/`.nav-call` go inert too, but not `<header>` itself — `.nav-toggle` lives inside it and has to stay clickable so it can close the dialog it just opened.

Panel semantics tightened 2026-08-15 (a technical-improvement-plan item): `#mobile-nav` is now `role="dialog" aria-modal="true"`, carries `inert` in its default closed HTML markup (removed on open, restored on close — the dialog itself was a real "hidden but still keyboard-focusable" bug caught by `html-validate`'s `hidden-focusable` rule before this fix), and `main.js` traps Tab focus inside it while open (looping from last focusable element back to first and vice versa) instead of only relying on `aria-hidden`. Focus moves to the first focusable element on open and is restored to whichever element had focus before opening (not always `.nav-toggle`) on close.

The breakpoint this panel and its scrim disappear above moved from 900px to 1100px in the same pass — see Layout above.

The link list is 8 items (Home, Flat Roofing, Recent Work, Why Choose Us, About, Reviews, FAQ, Contact — `.mobile-nav ul li:nth-child(1..8)` stagger delays cover all of them). Fixed 2026-08-16: the list previously had 7 items and used different labels than the desktop `.nav-links` for the same destinations ("Services"/"Testimonials" vs. desktop's "Flat Roofing"/"Reviews") and was entirely missing a link to Recent Projects — a real destination unreachable from the mobile menu on the device most visitors actually use. Labels now match desktop verbatim; if `.nav-links` copy changes, update this list too, and if an item is ever added or removed, update the `:nth-child` stagger-delay count to match.

## Do's and Don'ts

### Do:
- **Do** keep every primary CTA button amber-filled with navy text — never white text on amber.
- **Do** measure shape/spacing claims against a native-resolution crop of the reference before changing a radius or size value again — three rounds of "still too rounded" in this revision came from estimating off a scaled-down view instead of zooming in.
- **Do** treat `.is-highlight` (amber-tinted background, inset amber border) as a single-use highlight; if a second "featured" card is ever needed, reuse the same amber treatment rather than introducing a new color for it.
- **Do** keep any dense row of items placed in the hero horizontally scrollable (not wrapped) on narrow viewports — wrapping reintroduced a fixed-mobile-bar overlap bug once already, on the badge row this rule originally governed before it was replaced by a single compact trust line.
- **Do** set `min-width: 0` on any flex/grid item that contains a `nowrap` + `overflow-x: auto` descendant — omitting it lets the descendant force the ancestor wider than the viewport instead of scrolling internally.
- **Do** append a cache-busting `?v=N` query string to `styles.css`/`fonts.css`/`main.js` in **every** HTML file (all 8, not just `index.html`) and bump it on every CSS/JS change — the local dev server sends no cache headers, and a version bumped in some files but not others has caused real confusion more than once.
- **Do** re-check `no two adjacent sections share a register` and re-sync shared header/mobile-nav/footer markup across all 4 pages whenever either changes — there's no template engine catching drift for you.
- **Do** give every link/button a ≥44×44px tap target on mobile, including plain text links in the footer — `.footer-list a` and `.footer-contact a` were both under this until fixed 2026-08-16 (`padding-block` added, container `gap` reduced to compensate so the footer didn't grow taller than necessary).
- **Do** reinforce pricing (fair/transparent, no hidden costs), quality (premium, weather-resistant, built to last), and the free-inspection→honest-advice→free-quote funnel wherever it's natural to say so honestly — a 2026-08-17 pass (informed by a competitor marketing-pattern review) touched the hero primary CTA ("Call for a Free Inspection & Quote"), the Why Choose Us cards ("Premium, Weather-Resistant Materials" / "Fair, Transparent Pricing"), the free-quote FAQ answer, the About paragraph ("expert craftsmanship... attention to detail"), and the testimonials lede (explicitly naming the speed/honesty/price themes the real reviews already demonstrate). None of it added a new claim needing verification — see the Don't below on unverified claims.

### Don't:
- **Don't** add an eyebrow/kicker label above any heading, on this page or a new one — refused outright, not just avoided by default.
- **Don't** introduce a second accent color; amber (including its own tints for highlights) stays the only committed hue. A lime accent held the highlight role until 2026-08-15 and was removed for exactly this reason — don't bring it or another color back for the same job.
- **Don't** add a contact form, newsletter signup, or booking flow of any kind — unchanged hard constraint from PRODUCT.md.
- **Don't** build a new accordion/expand-collapse component without checking the reference first — the "service accordion" this system almost shipped was based on an assumption, not what the reference actually shows.
- **Don't** fabricate a customer count, review count, or avatar cluster (the reference's "1450+ Satisfied Customers" motif) — the hero's floating stat card shows the one number that's actually true, 30+ years.
- **Don't** adopt a build step, static-site generator, or template engine without revisiting PRODUCT.md first — "no build pipeline" is a hard constraint, not a style preference, and an Eleventy/Nunjucks proposal was declined for exactly this reason. (The site went multi-page then back to single-page in the same week — this constraint outlived both.)

**Real bug fixed 2026-08-16**: `.project-gallery img`/`.project-gallery--after img` initially omitted `height: auto`, and every tile rendered at the image's full native pixel height (1600–2040px) squeezed into a ~150–300px-wide column — the `aspect-ratio` CSS property was being silently ignored. Cause: the `<img>` elements carry HTML `height="..."` attributes (kept intentionally, for CLS purposes — see the `image-dimension` rule this whole site follows). An HTML `height` attribute maps to a low-priority but present `height` value in the cascade; since neither dimension was then `auto`, `aspect-ratio` had nothing left to resolve and was ignored per spec, even though `getComputedStyle` still reported `aspect-ratio: 3 / 4` as if it were active — the box size didn't reflect it.
